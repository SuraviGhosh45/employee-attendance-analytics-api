# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-38) | **Timezone ignorance & shift date:** Assumes `punch_in` is in local IST time and calls `punch_in.replace()`. If `punch_in` is UTC or across midnight for an overnight shift, the start time is calculated against the wrong day/timezone. | Punch in at `09:35 IST` from a UTC datetime object (`04:05 UTC`); `replace(hour=9)` sets UTC to 9, shifting calculation by 5.5 hours. | Convert `punch_in` to IST (+05:30) and build `shift_start_dt` using the attendance date (accounting for overnight shifts). |
| 2 | `compute_late_minutes` (lines 36-37) | **Strict 10-minute grace period violation (R2):** Calculates `minutes = int(seconds / 60)` then checks `minutes > 10`. At `09:40:01`, `total_seconds` is 601, `int(601/60)` is 10, so `10 > 10` evaluates to False and returns 0. Rule R2 requires late if *strictly more than* 10:00 (i.e. > 600 seconds), giving 10 minutes late. | Punch in at `09:40:01` for a `09:30` shift. Returns `0` instead of `10`. | Check `elapsed_seconds > 600`. If true, return `int(elapsed_seconds // 60)` (minutes since `shift_start`); otherwise return `0`. |
| 3 | `compute_work_hours` (lines 40-41) | **Banker's rounding (R4, R8):** Uses Python's built-in `round()`, which performs round-half-to-even. Contract requires standard half-up rounding. | A work duration of 2.125 hours produces `2.12` instead of `2.13`. | Use `decimal.Decimal` with `ROUND_HALF_UP` (or exact half-up arithmetic). |
| 4 | `compute_overtime` (lines 44-48) | **Minimum threshold ignored (R3):** Rule R3 requires overtime to be at least 30 minutes to count; otherwise 0. Starter returns `max(0, minutes)`, so any positive minutes (< 30) are wrongly credited. | Punching out 15 minutes after `shift_end` returns `15` instead of `0`. | Return `minutes if minutes >= 30 else 0`. |
| 5 | `compute_overtime` (lines 44-48) | **Overnight shifts not handled (R1, R3):** For overnight shifts (`shift_end <= shift_start`), `shift_end` falls on the next calendar day. Starter always constructs `end` on `date_str`, causing `shift_end` to be evaluated on the start date. | On an overnight shift 22:00 - 06:00 on 2026-07-06, punching out at 06:35 on 2026-07-07 gives ~1475 minutes overtime instead of 35. | Add 1 calendar day to `shift_end_dt` when `shift_end <= shift_start`. |
| 6 | `health` (lines 72-74) | **No MongoDB ping check:** Endpoint blindly returns `{"status": "ok"}` with 200 without checking if MongoDB is reachable. Spec requires 200 only if MongoDB answers a ping; else 503. | Stop MongoDB or pass invalid URI. `/health` still returns 200. | Ping MongoDB with `client.admin.command('ping')` inside a try-catch block; raise `HTTPException(503)` on failure. |
| 7 | `create_employee` (lines 78-86) | **Race condition on employee creation:** Uses check-then-insert (`find_one` then `insert_one`). Concurrent requests with identical `emp_code` race past the check and cause duplicates or unhandled 500 crashes. | Send concurrent identical `POST /employees` requests; both succeed or one raises unhandled `DuplicateKeyError` (500). | Create a unique index on `emp_code` at startup and catch `pymongo.errors.DuplicateKeyError`, converting it to HTTP 409. |
| 8 | `create_employee` (lines 81-85) | **Invalid timestamp format & schema violation:** `created_at` is set to `datetime.now()` (naive local datetime) and returned as such. OpenAPI contract requires epoch milliseconds integer. Also missing validation for `shift_start != shift_end`. | Response fails validation because `created_at` is a datetime/string instead of integer epoch milliseconds. Creating with identical shift start and end succeeds. | Set `created_at` to UTC datetime truncated to whole seconds; serialize to epoch milliseconds in response; validate `shift_start != shift_end`. |
| 9 | `list_employees` (line 93) | **Off-by-one pagination bug (R10):** Calculates `skip = page * page_size`. Since `page` is 1-indexed (starts at 1), page 1 skips `1 * 20 = 20` items, completely omitting records 1 to 20! | `GET /employees?page=1` returns items 21-40. Items 1-20 are permanently inaccessible. | Change skip formula to `(page - 1) * page_size`. |
| 10 | `list_employees` (line 94) | **Total count ignores filters (R10):** `total = db.employees.count_documents({})` counts the entire collection instead of the filtered subset. | Query with `?department=Sales` returns `total` as total company headcount rather than Sales headcount. | Count with filter: `db.employees.count_documents(q)`. |
| 11 | `list_employees` (lines 88-96) | **Missing sort order:** Contract requires employees sorted by `emp_code` ascending. Starter has no sort. | Returned employees appear in arbitrary database insertion order. | Add `.sort("emp_code", 1)` to the query. |
| 12 | `punch_in` (lines 100-106) | **Missing employee check (404):** Does `emp = db.employees.find_one(...)` without checking if `emp` exists. If `emp` is None, `emp["shift_start"]` raises `TypeError` (500). | Punch in with an unknown `emp_code`. Server returns 500 Internal Server Error instead of 404. | Check if `emp` is None and raise `HTTPException(404, "Employee not found")`. |
| 13 | `punch_in` (lines 104-118) | **Race condition on punch-in:** Relies on check-then-insert for `(emp_code, date)`. Simultaneous requests both pass the check. | Send concurrent punch-ins for the same employee and date; multiple records get inserted. | Enforce a unique index on `(emp_code, date)` and catch `DuplicateKeyError`, raising HTTP 409. |
| 14 | `punch_in` (lines 102-103) | **Incorrect date and instant truncation (R1):** Uses `ts.date().isoformat()` from local time without IST conversion. Also fails overnight shifts where punch-in before `shift_end` belongs to the previous day's shift. Fails to truncate instants to whole seconds. | Punch in at 05:00 IST for a 22:00 - 06:00 shift; assigned to today's date instead of yesterday's shift date. Milliseconds are preserved. | Convert instant to IST; if overnight shift and IST time < `shift_end`, assign date as `(ist_date - 1 day)`; truncate timestamp to whole seconds. |
| 15 | `punch_in` & models (lines 63-67) | **Missing validation for `punched_at` and `status`:** Allows invalid status (e.g. `ABSENT`, `LEAVE`) and accepts seconds-looking timestamps or floats instead of epoch milliseconds. | `POST /attendance/punch-in` with `{"status": "LEAVE"}` or `{"punched_at": 1720000000}` succeeds instead of 422. | Use Pydantic validator to restrict status to `PRESENT`, `WFH`, `ON_DUTY` and enforce `minimum: 100000000000` (epoch ms). |
| 16 | `punch_in` (lines 119-121) | **Response schema violation:** Injects `"id": str(res.inserted_id)`. The contract explicitly states `_id` is internal and never appears in requests or responses. `punch_in` returned as datetime instead of epoch ms. | Response contains `"id"` key and datetime string, failing OpenAPI schema. | Exclude `_id`/`id` completely and return `punch_in` as integer epoch milliseconds. |
| 17 | `list_attendance` (lines 144-150) | **Unbounded in-memory loading & slow query:** Loads all matching documents into memory with `list(db.attendance_logs.find(q))` and sorts in Python. Fails performance requirement at 100,000 documents. | Severe latency and memory spike when querying large datasets. | Use indexed MongoDB query with `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 18 | `list_attendance` (line 145) | **Incorrect sort specification:** Starter sorts only by `date` descending. Contract specifies `Sorted by date descending, then emp_code ascending`. | Records on the same date appear in indeterminate order. | Add compound sort `[("date", -1), ("emp_code", 1)]`. |
| 19 | `list_attendance` (lines 127-142) | **Missing date range validation:** Contract states `date_from > date_to -> 422`. Starter does not validate. | Query with `date_from=2026-07-10&date_to=2026-07-01` returns 200 instead of 422. | Check `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 20 | Startup lifecycle (lines 22-28) | **Indexes not created at startup:** App does not create database indexes on startup, violating the environment contract. | Seeded DB has only `_id` index; queries result in `COLLSCAN` and unique constraints fail. | Implement FastAPI lifespan handler that creates unique and query indexes on startup idempotently. |

---

### Non-Defects Examined
We also evaluated the following aspects in the codebase and verified that they are **not** defects:
1. **Use of customer-generated `emp_code` instead of MongoDB's `_id`:** The specification explicitly states that `emp_code` is the universal immutable business identifier and that MongoDB `_id` must remain internal.
2. **Storing calendar dates (`YYYY-MM-DD`) and shift times (`HH:MM`) as plain strings:** `DATA_MODEL.md` explicitly notes that calendar dates and times of day are plain strings on purpose, to prevent timezone contamination.
3. **Persisting derived values (`work_hours`, `late_minutes`, etc.) rather than computing on read:** `DATA_MODEL.md` specifies that stored derived values are authoritative, and analytics must read stored values.
